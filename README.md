# JFS 请求抓包器

Chrome 扩展，用于在 JFS（J&T Cargo 巴西快运系统）中自动拦截所有 XHR/fetch 请求，记录请求体和响应体，一键导出 JSON 用于排查报错。

---

## 为什么做这个工具

网点用户反馈"系统报错了"，常见的排查路径是：

1. 远程桌面上去复现——复现不出来
2. 让用户截图——小红字一闪而过，截不全
3. 等研发查后端日志——跨时区、跨语言、排队等

JFS 自带的日志模块只记"谁登录了、谁改了哪条数据"，**不记前端 HTTP 请求**。用户点保存被后端拒绝时，系统里查不到任何痕迹。

这个工具就是补这个缺口：**装一次，用户在浏览器里的所有请求自动留痕，报错时一键导出**。

---

## 能解决什么问题

| 场景 | 没有这个工具 | 有这个工具 |
|---|---|---|
| 用户说"我建线失败了" | 问用户点了哪个按钮、报了什么错 | 直接看：哪个接口、发了什么参数、后端返回的 `msg` 原文 |
| 评估开发说"这个需求要 3 天" | 只能信 | 看接口复杂度，如果就是个 CRUD，3 天就离谱 |
| 想知道某个按钮点了之后系统干了啥 | 问研发 | 自己看请求/响应就明白 |
| 跨时区支持巴西网点 | 等用户上班、等翻译 | 拿到 JSON 直接定位，不用懂葡萄牙语 |
| 量化"哪个模块体验最差" | 凭感觉 | 聚合一个月数据，看哪个模块报错最多、哪个接口最慢 |

---

## 功能

- 自动拦截 XHR 和 fetch 请求（method、URL、request body、HTTP 状态码、response body）
- 失败请求自动标红（HTTP ≥400 或后端 `code != 1`）
- 悬浮按钮可自由拖动，位置自动记忆（localStorage）
- 面板可通过标题栏拖动
- URL 过滤、只看失败
- 一键导出 JSON 文件
- 最多保留 2000 条请求

---

## 安装（开发者模式）

1. 下载本仓库代码
2. 打开 Chrome，地址栏输入 `chrome://extensions/`
3. 右上角打开"开发者模式"
4. 把文件夹拖进页面，或点"加载已解压的扩展程序"选择本目录
5. 打开 `https://jfs.jtcargo.com.br`，右下角出现蓝色圆形按钮即安装成功

---

## 使用

1. 正常操作 JFS，所有请求自动记录
2. 遇到报错时，按钮变红
3. 点按钮弹出面板，勾选"只看失败"
4. 点击红色请求行，展开 REQUEST/RESPONSE 详情
5. 点"导出 JSON"下载日志文件

---

## 适合谁用

- **IT 产品经理**：不用等研发讲，自己就能搞清楚按钮背后调了什么接口、参数怎么传
- **运维/IT 支持**：网点报错不用远程桌面，拿到 JSON 30 秒定位
- **实施/上线**：新网点铺开时，验证配置有没有生效
- **QA**：改了功能后，diff 一下请求变化，不用全量回归

---

## 它不能做什么（边界）

- 看不到数据库里到底存了什么
- 看不到后端业务规则的完整判定逻辑（要问研发或看代码）
- 不能替代正经的监控系统（Sentry/Prometheus/ELK）
- 只能在装了这个扩展的浏览器里抓

一句话：它是个**轻量、零部署、装在用户浏览器里**的诊断工具。正经的可观测性要靠研发搭基础设施，但这个工具让你不等基础设施，先有一双能看见请求的眼睛。

## 文件结构

```
jfs-trace-extension/
├── manifest.json      # Chrome 扩展配置（Manifest V3）
└── content_script.js  # 拦截器 + 悬浮 UI
```

## 技术说明

- 使用 Manifest V3 的 `world: "MAIN"` 模式直接在页面主世界注入，能 hook 到 Vue/axios 发出的请求
- 只匹配 `https://jfs.jtcargo.com.br/*`
- 自动过滤噪音请求（userAccessLog、checkToken、notice）
